# LRRec

LRRec is a PyTorch library for **language-representation (LR)-based recommendation**: recommenders built on
frozen item embeddings from a language model (for example OpenAI text-embedding-3-large or LLaMA-3-8B) instead of,
or in addition to, learned item IDs.

- **Code structure from [MMRec](https://github.com/enoche/MMRec):** layered YAML configs, models looked up by
  name, `GeneralRecommender` + `Trainer`, built-in grid search.
- **Data and protocol from [AlphaFree](https://github.com/Minseojeonn/AlphaFree) (WWW'26):** the 7 AlphaFree
  datasets in their original on-disk format, the same training sampler and the same full-ranking evaluation.

The official AlphaFree checkpoints reproduce the official test numbers when evaluated with LRRec (see
[Verification](#verification-against-the-official-alphafree-release)).

## Models

| `-m` | Type | Idea | Loss | Paper |
|---|---|---|---|---|
| `AlphaFree` | LR-based | No user embeddings, no item IDs, no GNN. User LR = weighted sum of history LRs; an MLP maps LRs to the recommendation space; co-occurrence + LR-similarity augmentation gives a second view | InfoNCE (original + augmented view) + alignment | Jeon et al., *AlphaFree: Recommendation Free from Users, IDs, and GNNs*, WWW 2026 |
| `AlphaRec` | LR-based | User LR = mean of history LRs; shared MLP on LRs, then LightGCN propagation | InfoNCE on cosine scores | Sheng et al., *Language Representations Can be What Recommenders Need: Findings and Potentials*, ICLR 2025 |
| `LightGCN` | ID-based baseline | ID embeddings + LightGCN propagation (mean of layers 0..L) | BPR + L2 | He et al., SIGIR 2020 |
| `XSimGCL` | ID-based baseline | LightGCN + noise-perturbed cross-layer contrastive learning | BPR + InfoNCE + L2 | Yu et al., TKDE 2023 |

Each model is a single file in [`src/models/`](src/models) with the equations in its docstring.

## Installation

Requirements: Linux, one CUDA GPU, Python 3.10, PyTorch 2.1.2. Pinned versions are in
[`requirements.txt`](requirements.txt).

```bash
git clone https://github.com/Myungbin/LRRec.git
cd LRRec

conda create -n lrrec python=3.10 -y
conda activate lrrec
pip install torch==2.1.2 --index-url https://download.pytorch.org/whl/cu121   # pick the CUDA build for your driver
pip install -r requirements.txt
```

scripts/download_data.sh                           # all 7 datasets + checkpoints
scripts/download_data.sh --dataset Movie,Video     # selected datasets (paper names, see the table below)
DATA_DIR=/path/to/storage scripts/download_data.sh # download somewhere else

```bash
ln -s /path/to/storage LRRec/data       # or set data_path in src/configs/overall.yaml
```

### On-disk format

LRRec reads the AlphaFree files as they are and never writes to `cf_data/` or `item_info/`:

```
data/
├── <dataset>/
│   ├── cf_data/
│   │   ├── train.txt                    "<user> <item> <item> ..." one line per user, 0-based ids
│   │   ├── valid.txt                    same format
│   │   └── test.txt                     same format
│   ├── item_info/
│   │   └── item_cf_embeds_*_array.npy   item LRs, row i = item i (large3 = v3, LLAMA = llama)
│   └── preprocessed/                    AlphaFree augmentation caches (shipped, and built by LRRec on first use)
└── pretrained/<dataset>.pth.tar         official AlphaFree checkpoints
```

[`RecDataset`](src/utils/dataset.py) turns the three split files into one MMRec-style table
`[userID, itemID, x_label]` with `x_label` 0 / 1 / 2 = train / valid / test. The number of users is the largest
user id + 1, and the number of items is the largest item id + 1 (or `cf_data/n_items.txt`, if present). For
models with `is_lr_model: True`, `GeneralRecommender` loads the LR file named in `configs/dataset/<dataset>.yaml`
as `self.lr_feat` (`n_items × d`, float32, on the GPU); this replaces MMRec's `v_feat` / `t_feat`.

## Quick start

```bash
cd src     # every command runs from src/

# 1. check the setup: evaluate the official AlphaFree checkpoint on Movie (test Recall@20 must be 0.1263)
python main.py -m AlphaFree -d amazon_movie -g 0 --eval_only --model_path ../data/pretrained/amazon_movie.pth.tar

# 2. a 2-epoch smoke test
python main.py -m AlphaFree -d amazon_movie -g 0 --epochs 2 --eval_step 1 --tag smoke

# 3. a full training run with the tuned hyper-parameters
python main.py -m AlphaFree -d amazon_movie -g 0
```

The other models run the same way:

```bash
python main.py -m AlphaRec -d amazon_movie -g 0
python main.py -m LightGCN -d amazon_video -g 0
python main.py -m XSimGCL  -d amazon_video -g 0
```

## Command-line usage

```
python main.py -m <MODEL> -d <DATASET> [-g GPU] [-s] [-t TAG] [--eval_only --model_path PATH] [--<key> <value> ...]
```

| Argument | Default | Meaning |
|---|---|---|
| `-m`, `--model` | `AlphaFree` | model class name (`AlphaFree`, `AlphaRec`, `LightGCN`, `XSimGCL`) |
| `-d`, `--dataset` | `amazon_movie` | dataset directory name under `data/` |
| `-g`, `--gpu_id` | `0` | GPU index (sets `CUDA_VISIBLE_DEVICES`) |
| `-s`, `--save_model` | off | save the best checkpoint (by validation score) in the run directory |
| `-t`, `--tag` | none | label appended to the run directory name |
| `--eval_only` | off | evaluate `--model_path` on valid and test without training |
| `--model_path` | none | a LRRec `state_dict` or an official AlphaFree `{'epoch', 'state_dict'}` checkpoint |
| `--<key> <value>` | | override any config key; the value is parsed as YAML |

Examples of overrides:

```bash
# scalars
python main.py -m AlphaFree -d amazon_video -g 0 --tau_r 0.15 --learning_rate 1e-3

# a list value + hyper_parameters = grid search (cartesian product, best combination chosen on validation)
python main.py -m AlphaRec -d amazon_movie -g 0 --tau "[0.1,0.15,0.2]" --hyper_parameters "[tau]"
python main.py -m AlphaFree -d amazon_movie -g 0 --K_c "[3,5,10]" --lambda_align "[0.1,0.2]" \
    --hyper_parameters "[K_c,lambda_align]"

# several seeds (seed is always part of the grid)
python main.py -m AlphaFree -d amazon_movie -g 0 --seed "[2024,2025,2026]"

# MMRec's evaluation protocol instead of AlphaFree's
python main.py -m LightGCN -d amazon_movie -g 0 --eval_protocol mmrec
```

`--key=value` also works. A flag without a value is read as `true`.

## Configuration

A run's config is merged from five sources, later ones overriding earlier ones:

```
configs/overall.yaml                        global defaults
  < configs/dataset/<dataset>.yaml          LR file and language model of the dataset
  < configs/model/<MODEL>.yaml              model defaults
  < dataset_params[<dataset>]               tuned values for this dataset, inside the model yaml
  < command line (--key value)
```

Models read values with `config['key']`, which returns `None` for missing keys.

Main keys of [`configs/overall.yaml`](src/configs/overall.yaml):

| Key | Default | Meaning |
|---|---|---|
| `seed` | `[2026]` | random seed(s) |
| `deterministic` | `True` | deterministic CUDA kernels (see [Reproducibility](#reproducibility)) |
| `data_path` | `'../data/'` | root of the datasets, relative to `src/` |
| `is_lr_model` | `True` | load the item LRs as `self.lr_feat` (`False` in the ID-based model configs) |
| `embedding_size` | `64` | output dimension of every model |
| `epochs` | `500` | maximum number of epochs |
| `train_batch_size` | `4096` | training batch size |
| `learner` | `adam` | `adam`, `adamw`, `sgd`, `adagrad` or `rmsprop` |
| `learning_rate` | `0.0005` | learning rate |
| `weight_decay` | `0.0` | optimizer weight decay |
| `learning_rate_scheduler` | `[1.0, 50]` | `lr × a^(epoch / b)`; `[1.0, 50]` keeps it constant |
| `clip_grad_norm` | `~` | e.g. `{max_norm: 5}` to clip gradients |
| `train_sampling` | `user` | training sampler, `user` or `interaction` |
| `neg_sample_num` | `1` | negatives per training sample; `0` = in-batch negatives |
| `eval_step` | `5` | evaluate every N epochs |
| `stopping_step` | `20` | stop after N evaluations without improvement |
| `eval_protocol` | `alphafree` | `alphafree` or `mmrec` |
| `mask_valid_for_test` | `False` | `mmrec` protocol only: also mask valid items when ranking for test |
| `metrics` / `topk` | `["Recall", "NDCG"]` / `[10, 20, 50]` | reported metrics |
| `valid_metric` | `Recall@20` | metric for early stopping and for picking the best combination |
| `eval_batch_size` | `4096` | users per full-ranking batch |
| `save_recommended_topk` | `False` | write the top-K lists of every test evaluation to `recommend_topk/` |
| `hyper_parameters` | `["seed"]` | keys to sweep |
| `show_progress` | `False` | tqdm bar per training epoch |

## Training and evaluation protocol

The defaults reproduce the AlphaFree repository.

### Training

- **Sampler (`train_sampling`)**
  - `user` (default): every epoch draws as many samples as there are training interactions. Samples are
    assigned to users cyclically through a random permutation, so every user is visited about equally often.
    The positive is drawn uniformly from the user's training items. The last incomplete batch is dropped.
  - `interaction` (MMRec): every training (user, item) pair appears once per epoch in random order.
- **Negatives (`neg_sample_num`):** drawn uniformly from all items except the user's training items (rejection
  sampling on the GPU). A training batch is `[users, pos_items, neg_items]`, where `neg_items` has shape `(B,)`
  for 1 negative and `(B, N)` for N negatives, and is absent for `0` (in-batch negatives).
- **Loss:** the mean over the batch, as returned by `calculate_loss`.
- **Early stopping:** valid and test are evaluated every `eval_step` epochs. Training stops after
  `stopping_step` evaluations without improvement in `valid_metric`. The reported test result is the one at the
  best validation epoch.
- **Grid search:** every combination is trained from scratch with its own seed. The best combination is chosen
  on **validation**; test is only reported.

### Evaluation

Full ranking over all items for every user who has at least one item in the evaluated split.

| `eval_protocol` | Valid ranks with these items removed | Test ranks with these items removed |
|---|---|---|
| `alphafree` (default) | train + test | train + valid |
| `mmrec` | train | train (+ valid with `mask_valid_for_test`) |

Under `alphafree`, a positive of the evaluated split is never removed, even if it also occurs in another split.
Removed items get the score `-1e10` before the top-K.

Metrics are averaged over the evaluated users, with the definitions of the AlphaFree evaluator. With `G` the
user's positives in the split and `rel_k = 1` if the item at rank k is in `G`:

- `Recall@K = |top-K ∩ G| / |G|`
- `NDCG@K = DCG@K / IDCG@K`, `DCG@K = Σ_{k=1..K} rel_k / log2(k + 1)`, IDCG over `min(|G|, K)` hits

### Reproducibility

`init_seed` seeds Python, NumPy and PyTorch. With `deterministic: True` it also calls
`torch.use_deterministic_algorithms(True, warn_only=True)`, and `main.py` sets `CUBLAS_WORKSPACE_CONFIG`.
Negative sampling uses a dedicated generator seeded at the start of every run. Two AlphaFree runs with the same
seed and config give identical losses and metrics on the same GPU type, with no measurable slowdown. Operations
without a deterministic CUDA kernel log a warning instead of failing, so the graph models (sparse matrix
products) may still vary slightly between runs.

## Model hyper-parameters

### AlphaFree ([`configs/model/AlphaFree.yaml`](src/configs/model/AlphaFree.yaml))

The training settings are those of the official code: Adam, learning rate 5e-4, batch 4096, 256 negatives.

| Key | Default | Meaning |
|---|---|---|
| `tau_r` | 0.15 | temperature of the recommendation InfoNCE |
| `tau_a` | 0.2 | temperature of the alignment loss |
| `lambda_align` | 0.2 | weight of the alignment loss |
| `K_c` | 5 | co-occurring candidates per item for the augmentation |
| `sim_b` | `raw` | co-occurrence score: `raw` count, or `cosine` = count / sqrt(deg_i · deg_j) |
| `exclude_self` | `False` | drop the item itself from its candidates |
| `aug_mode` | `both` | input of the augmented view: `both`, `inter` (augmented interactions, original LRs), `rep` (original interactions, augmented LRs), `none` |

Both MLPs map `d_LR → hidden → 64`, with the hidden size `d_LR / 2` for `v3` and `9 · d_LR / 32` for `llama`
(`LM_MLP_RATIO` in [`common/abstract_recommender.py`](src/common/abstract_recommender.py)), as in the official
code. The values tuned for each dataset in the official repository are applied automatically:

| Dataset | `K_c` | `lambda_align` | `tau_a` | `tau_r` |
|---|--:|--:|--:|--:|
| Movie | 5 | 0.2 | 0.2 | 0.15 |
| Book | 5 | 0.2 | 0.1 | 0.15 |
| Video | 10 | 0.05 | 0.01 | 0.2 |
| Baby | 10 | 0.01 | 0.2 | 0.2 |
| Steam | 3 | 0.01 | 0.2 | 0.2 |
| Beauty | 10 | 0.01 | 0.1 | 0.2 |
| Health | 5 | 0.01 | 0.2 | 0.15 |

The augmentation is built once per (`lm_model`, `K_c`, `sim_b`, `exclude_self`) and cached in
`data/<dataset>/preprocessed/<lm_model>_Kc<K_c>_simb<sim_b>_selfexcl<0|1>/` (`user_interact_matrix.npz`,
`aug_user_interact_matrix.npz`, `item_cf_embeds_augmented.npy`). The first run on Beauty or Health takes a few
minutes and about 18 GB of RAM for this step. Only `mlp_origin` is used at inference. The parameter names match
the official checkpoints, which therefore load with `strict=True`.

### AlphaRec ([`configs/model/AlphaRec.yaml`](src/configs/model/AlphaRec.yaml))

| Key | Default | Meaning |
|---|---|---|
| `n_layers` | 2 | LightGCN layers |
| `tau` | 0.15 | InfoNCE temperature (the AlphaRec value for Movies and Books; tune for other datasets) |

Learning rate 5e-4, batch 4096, 256 negatives. AlphaRec keeps a dense `n_users × d_LR` user-LR matrix and
propagates the full graph at every step; the AlphaFree paper reports it as out of GPU memory on Beauty and Health.

### LightGCN and XSimGCL ([`LightGCN.yaml`](src/configs/model/LightGCN.yaml), [`XSimGCL.yaml`](src/configs/model/XSimGCL.yaml))

Both are ID-based (`is_lr_model: False`) and use BPR with 1 negative, learning rate 1e-3 and batch 2048.

| Key | Model | Default | Meaning |
|---|---|---|---|
| `n_layers` | both | 3 | propagation layers |
| `reg_weight` | both | 1e-4 | L2 weight on the batch's layer-0 embeddings |
| `eps` | XSimGCL | 0.1 | magnitude of the signed uniform noise added after every layer |
| `layer_cl` | XSimGCL | 1 | layer contrasted with the final representation (1-indexed) |
| `lambda_cl` | XSimGCL | 0.2 | weight of the contrastive loss |
| `tau_cl` | XSimGCL | 0.2 | temperature of the contrastive loss |

Values tuned on validation Recall@20 (seed 2026) are included for Movie and Video only:

| Model | Movie | Video |
|---|---|---|
| LightGCN | `n_layers` 3, `reg_weight` 1e-3 | `n_layers` 4, `reg_weight` 1e-3 |
| XSimGCL | `n_layers` 5, `layer_cl` 1, `eps` 0.1, `lambda_cl` 0.1 | `n_layers` 5, `layer_cl` 5, `eps` 0.01, `lambda_cl` 0.01 |

The other datasets use the defaults above, which are not tuned.

| Dataset | LRRec Recall@20 | LRRec NDCG@20 | Official code, seed 2026 | Paper |

The best validation epoch was 209 (valid Recall@20 0.1272). Training took about 17 s per epoch and 1.5 hours in

### Augmentation

The rebuilt augmentation matches the official `preprocessed/` files: the L1-normalized interaction matrix and z+
are identical. The augmented interaction matrix differs in a few entries (1 of 1.34M on Movie, 102 of 2.37M on
Video) because LRRec follows the paper, I⁺ = I ∪ (∪ S_i), and the official code leaves out the explicit ∪ I.

## Adding a model

1. Create `src/models/<name>.py` with a class whose name is exactly the `-m` argument (`MyRec` in `myrec.py`):

   ```python
   import torch
   import torch.nn.functional as F

   from common.abstract_recommender import GeneralRecommender


   class MyRec(GeneralRecommender):
       def __init__(self, config, dataloader):
           super().__init__(config, dataloader)        # sets n_users, n_items, device, lr_feat
           d = self.lr_feat.shape[1]                     # requires is_lr_model: True
           self.mlp = torch.nn.Linear(d, config["embedding_size"])
           self.user_emb = torch.nn.Embedding(self.n_users, config["embedding_size"])

       def calculate_loss(self, interaction):
           users, pos, neg = interaction[0], interaction[1], interaction[2]   # neg: (B,) with neg_sample_num 1
           items = self.mlp(self.lr_feat)
           u = self.user_emb(users)
           pos_scores = (u * items[pos]).sum(-1)
           neg_scores = (u * items[neg]).sum(-1)
           return -F.logsigmoid(pos_scores - neg_scores).mean()

       def full_sort_predict(self, interaction):
           users = interaction[0]
           return self.user_emb(users) @ self.mlp(self.lr_feat).T   # (batch users, n_items)
   ```

2. Create `src/configs/model/MyRec.yaml`:

   ```yaml
   is_lr_model: True        # False for ID-only models
   neg_sample_num: 1
   learning_rate: 0.001
   hyper_parameters: []
   ```

3. Run `python main.py -m MyRec -d amazon_movie -g 0`. There is no registry to edit.

Notes:

- `calculate_loss` returns a scalar. `full_sort_predict` returns the scores of `interaction[0]` against all
  items; the Trainer removes masked items itself.
- The Trainer calls `model.train()` before each epoch and `model.eval()` before evaluation. Models that cache
  item embeddings for evaluation clear the cache in `train()`.
- `self.lr_feat` is a plain tensor, not a parameter or buffer, so it is not saved in checkpoints. Do not modify
  it in place.

## Differences from the source repositories

- **From AlphaFree:** LRRec contains only the paper model. The research extensions of the AlphaFree fork the
  port started from (`fuse_text`, `moe`, `pop_bias`, `lambda_sem`, hard-negative mining, `lr_whiten`, ...) are
  not included. The augmentation options `sim_b`, `exclude_self` and `aug_mode` are kept, with the paper
  defaults. The augmented interaction set follows the paper (see [Augmentation](#augmentation)).
- **From MMRec:**
  - With several hyper-parameter combinations, the best one is selected on validation (MMRec selects on test).
  - Hits are computed on the GPU, and the AlphaFree evaluation protocol is the default.
  - Multimodal-only parts (image/text feature loading, lmdb, cold-start utilities, diagnostics, visualizer)
    are removed.
  - The `user` sampler and multi-negative batches are new.
